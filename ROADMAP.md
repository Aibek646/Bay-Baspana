# BAY BASPANA — план работ

Путь развития: **A — отдельный инстанс на каждого клиента** (свой Supabase + свой деплой).
Переход к общей базе на несколько агентств запланирован как этап 6, но не раньше, чем
появится второй клиент на том же деплое.

Формат: идём сверху вниз, этап целиком, без перескоков. Внутри этапа порядок пунктов важен.

## Этап 4 — из каталога в инструмент

Делать после того, как коллега попользуется неделю-две: он сам скажет, что важнее.
Пункты 4.1, 4.2 и 4.6 входят в оплаченный объём работ — они обещаны при продаже.

- [ ] 4.1 Поля объекта: комнаты, площадь, этаж/этажность, ЖК, год постройки
- [ ] 4.2 Поиск и фильтры: район, диапазон цены, комнаты, «скрыть проданные», рассрочка
- [ ] 4.3 Сортировка (цена, дата) и пагинация
- [ ] 4.4 Даты «добавлено / продано» → отчёт «сколько продали за месяц»
- [ ] 4.5 Отдельная ссылка-подборка под конкретного клиента вместо всего каталога
- [ ] 4.6 Смена пароля в приложении: экран «Сменить пароль» для вошедшего
      (`supabase.auth.updateUser`) и обработка события `PASSWORD_RECOVERY` для
      письма «Забыли пароль». Сейчас пароль меняется только через дашборд Supabase,
      то есть клиенту недоступно вообще.

**Готово, когда:** при 100+ объектах найти нужный занимает секунды, а пароль
клиент меняет сам, не обращаясь к разработчику.

## Этап 6 — агентства (переход к пути B)

Идея нужная, но включается по триггеру: **данные двух разных фирм должны оказаться
в одной базе**. Например, друг пускает партнёров из других агентств, или третий-четвёртый
клиент делает ручные развёртывания дороже переписывания.

- [ ] 6.1 Таблица `agencies`, `agencyId` в `profiles` и `apartments` (`cities` остаётся общим)
- [ ] 6.2 Функция `current_agency_id()`, `default public.current_agency_id()` на `apartments`
      — тогда фронт про агентство даже не знает
- [ ] 6.3 Политики: `is_staff() and "agencyId" = current_agency_id()`
- [ ] 6.4 Индекс по `agencyId` (колонка попадает в каждый запрос через RLS)
- [ ] 6.5 `agencyId` в витрину `apartments_public`, публичные ссылки вида `/a/:slug`
- [ ] 6.6 Самостоятельная регистрация агентства, тарифы, биллинг

SQL для 6.1-6.5 разобран в переписке — при возврате к этапу поднять оттуда.

**Готово, когда:** два агентства в одной базе не видят друг друга, и это подтверждено
проверкой из браузера, а не из SQL Editor.
